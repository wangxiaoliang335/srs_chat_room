# 房间分享功能 — 服务端需求文档

## 1. 概述

实现房间分享功能：用户将房间分享到外部（微信、QQ、系统分享等），接收方通过链接可快速加入房间。

### 核心流程

1. **分享方**：房主在房间内点击"分享"，传入附言；服务端生成一个带唯一标识的分享链接，存活 1 天
2. **接收方**：点击链接 →
   - **普通解析（App 内打开）**：携带有效 JWT → 返回房间信息，直接加入
   - **公共解析（其他应用打开）**：检测到未在指定 App 中 → 尝试唤起 App，未安装则跳转下载页

## 2. 数据模型

### 2.1 分享记录 `ShareLink`

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 唯一 ID，格式 `share_<12位随机字符>` |
| room_id | string | 房间 ID |
| room_name | string | 房间名称 |
| sharer_id | string | 分享者 user_id |
| sharer_name | string | 分享者用户名 |
| message | string | 分享附言（由分享方输入） |
| created_at | int | 创建时间戳（Unix 秒） |
| expires_at | int | 过期时间戳（创建后 1 天） |
| status | string | `active` / `expired` |

## 3. HTTP API

基础 URL：`http://{host}:8085`

> 以下接口均需 `Authorization: Bearer <聊天服务器 JWT>`，除非特别标注。

### 3.1 生成分享链接

```
POST /api/v1/share
```

**请求体：**

```json
{
  "room_id": "room_xxx",
  "message": "快来一起聊天！"
}
```

**逻辑：**
1. 校验分享者是 `room_id` 的房主（`is_owner=true`）
2. 校验分享者在房间中
3. 生成唯一 `share_id`（格式 `share_<12位随机字符>`）
4. 创建分享记录 `sharer_id` = 当前 JWT user_id，状态 `active`
5. 返回完整分享 URL（内置 JWT 和 `message`）

**成功响应：**

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "share_id": "share_abc123def456",
    "share_url": "https://alove.app/room/share_abc123def456",
    "room_id": "room_xxx",
    "room_name": "闲聊室",
    "expires_at": 1785911054
  }
}
```

**错误码：**

| HTTP 状态码 | code | message | 说明 |
|-------------|------|---------|------|
| 403 | 403 | not room owner | 非房主不能分享房间 |
| 400 | 400 | sharer not in room | 分享者不在房间 |
| 404 | 404 | room not found | 房间不存在 |
| 400 | 400 | message too long | 附言超过 200 字 |

### 3.2 普通解析（App 内打开，需 JWT）

```
GET /api/v1/share/{share_id}/resolve
```

**说明：** 在指定 App 内打开分享链接时调用。需要 `Authorization: Bearer <JWT>`（即 chat_token）。返回详细房间信息供 App 直接展示并加入。

**请求头：**

```
Authorization: Bearer <JWT>
```

**逻辑：**
1. 校验 JWT 有效，解析当前用户身份
2. 查询 `share_id` 对应的分享记录，校验 `active` 且未过期
3. 检查房间是否存在且未关闭
4. 返回完整房间信息

**成功响应：**

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "share_id": "share_abc123def456",
    "room_id": "room_xxx",
    "room_name": "闲聊室",
    "sharer_id": "user_xxx",
    "sharer_name": "Alice",
    "message": "快来一起聊天！",
    "room_status": "active",
    "member_count": 5,
    "owner_id": "user_xxx",
    "your_role": "member",
    "expires_at": 1785911054
  }
}
```

**错误码：**

| HTTP 状态码 | code | message | 说明 |
|-------------|------|---------|------|
| 401 | 401 | not authenticated | JWT 缺失或无效 |
| 401 | 401 | invalid token | JWT 无效或已过期 |
| 404 | 404 | share link not found | 分享链接不存在 |
| 410 | 410 | share link expired | 分享链接已过期 |
| 404 | 404 | room not found or closed | 房间已被关闭或不存在 |

### 3.3 公共解析（其他应用打开，无需 JWT）

```
GET /api/v1/share/{share_id}
```

**说明：** 在微信/QQ/浏览器等外部应用中打开分享链接时调用。**无需鉴权**，仅返回基本房间信息和分享者信息，用于落地页展示。落地页根据返回数据决定唤起 App 或跳转下载。

**逻辑：**
1. 查询 `share_id` 对应的分享记录
2. 校验状态为 `active` 且未过期
3. 检查房间是否存在且未关闭
4. 返回基本信息

**成功响应：**

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "share_id": "share_abc123def456",
    "room_id": "room_xxx",
    "room_name": "闲聊室",
    "sharer_name": "Alice",
    "message": "快来一起聊天！",
    "room_status": "active",
    "member_count": 5,
    "expires_at": 1785911054
  }
}
```

**错误码：**

| HTTP 状态码 | code | message | 说明 |
|-------------|------|---------|------|
| 404 | 404 | share link not found | 分享链接不存在 |
| 410 | 410 | share link expired | 分享链接已过期 |
| 404 | 404 | room not found or closed | 房间已被关闭或不存在 |

### 3.4 通过分享链接加入房间

```
POST /api/v1/share/{share_id}/join
```

**说明：** 接收方通过分享链接加入房间。需要 JWT。

**请求体：**

```json
{}
```

**逻辑：**
1. 校验分享链接有效且未过期
2. 校验房间存在且状态为 `active`
3. 校验当前用户（JWT）不在房间中（已在则直接返回成功）
4. 调已有接口 `POST /api/v1/room/{room_id}/join` 将用户加入房间
5. 向房间内广播 `member_joined` WS 事件

**成功响应：**

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "room_id": "room_xxx",
    "room_name": "闲聊室",
    "share_id": "share_abc123def456"
  }
}
```

**错误码：**

| HTTP 状态码 | code | message | 说明 |
|-------------|------|---------|------|
| 401 | 401 | not authenticated | 未登录 |
| 404 | 404 | share link not found | 分享链接不存在 |
| 410 | 410 | share link expired | 分享链接已过期 |
| 404 | 404 | room not found or closed | 房间不存在或已关闭 |
| 400 | 400 | already in room | 已在房间中 |

## 4. 深度链接 / App Links 方案

### 4.1 URL 结构

| 用途 | URL |
|------|-----|
| 分享链接（HTTP） | `https://alove.app/room/{share_id}` |
| App 深度链接（Android） | `aloveapp://room/{share_id}?token={jwt}&message={message}` |
| App 深度链接（iOS） | `aloveapp://room/{share_id}?token={jwt}&message={message}` |

### 4.2 落地页行为

`https://alove.app/room/{share_id}` 是公共解析的落地页（轻量 HTML），在微信/QQ/浏览器等外部应用中打开时展示。

**页面加载时：**
1. 调用 `GET /api/v1/share/{share_id}`（公共解析）获取房间基本信息
2. 检测当前环境（UA 判断 + 尝试唤起）：
   - **Android**：尝试通过 Intent URI Scheme 唤起 App → `aloveapp://room/{share_id}?token={jwt}`
   - **iOS**：尝试通过 Universal Link 或 URL Scheme 唤起 App
   - **PC / 其他**：显示房间信息和二维码，提示扫码打开
3. 唤起成功 → App 内走 **普通解析** 流程
4. 唤起失败（超时或未检测到 App）→ 跳转应用商店下载页
   - Android：`https://play.google.com/store/apps/details?id=com.tyd.alove`
   - iOS：`https://apps.apple.com/app/idxxxxxxxxx`

**落地页应包含：**
- 分享者昵称和附言
- 房间名称
- 房间当前人数
- "打开 App 加入"按钮
- 若未安装则显示"下载 App"按钮

### 4.3 App 内深度链接处理（普通解析）

App 需要注册 URL Scheme `aloveapp://` 和 App Links（Android） / Universal Links（iOS）。

**分享链接中的 token：**

服务端生成 `share_url` 时内置 JWT（即 chat_token），格式为：
```
aloveapp://room/{share_id}?token={jwt}&message={message}
```

JWT 即用户当前的登录令牌，分享时服务端将其编入链接，使接收方在 App 内唤起时可直接鉴权。

**App 内处理流程：**

```
收到 aloveapp://room/{share_id}?token={jwt}&message={message}

1. 解析 share_id、jwt、message

2. 调用 GET /api/v1/share/{share_id}/resolve（普通解析）
   请求头携带 Authorization: Bearer {jwt}

3. 解析成功 → 返回房间详细信息，直接打开房间页面

4. 解析失败：
   a. JWT 无效/过期 → 跳转登录页，登录后用户手动加入
   b. 分享链接已过期 → 提示"分享已过期"
   c. 房间已关闭 → 提示"房间已关闭"
```

### 4.4 Android App Links 配置

```xml
<!-- AndroidManifest.xml -->
<intent-filter android:autoVerify="true">
    <action android:name="android.intent.action.VIEW" />
    <category android:name="android.intent.category.DEFAULT" />
    <category android:name="android.intent.category.BROWSABLE" />
    <data
        android:scheme="https"
        android:host="alove.app"
        android:pathPrefix="/room/" />
</intent-filter>

<intent-filter>
    <action android:name="android.intent.action.VIEW" />
    <category android:name="android.intent.category.DEFAULT" />
    <category android:name="android.intent.category.BROWSABLE" />
    <data
        android:scheme="aloveapp"
        android:host="room" />
</intent-filter>
```

### 4.5 iOS Universal Links 配置

```json
// apple-app-site-association
{
  "applinks": {
    "apps": [],
    "details": [
      {
        "appID": "TEAMID.com.tyd.alove",
        "paths": ["/room/*"]
      }
    ]
  }
}
```

### 4.6 iOS URL Scheme 配置

```xml
<!-- Info.plist -->
<key>CFBundleURLTypes</key>
<array>
    <dict>
        <key>CFBundleURLSchemes</key>
        <array>
            <string>aloveapp</string>
        </array>
    </dict>
</array>
```

## 5. 分享链接过期清理

服务端定期扫描 `status=active` 且 `expires_at < now` 的分享记录，自动标记为 `expired`（建议每小时执行一次）。

## 7. 完整调用时序

### 场景 A：分享方分享房间

```
1. 用户在房间内点击"分享"
2. 客户端 POST /api/v1/share
   { "room_id": "room_xxx", "message": "快来一起聊天！" }
   → 200 { "share_url": "https://alove.app/room/share_abc123def456" }
3. 客户端调用系统分享，将 share_url 发送到微信/QQ等
4. （可选）服务端广播 WS room_shared 事件
```

### 场景 B：接收方已安装 App 且已登录

```
1. 接收方点击 https://alove.app/room/share_abc123def456
2. 落地页加载，尝试唤起 App（携带 JWT）
3. App 收到 aloveapp://room/share_abc123def456?token=xxx
4. App 调用 GET /api/v1/share/share_abc123def456/resolve（普通解析）
5. 解析成功，打开房间页面
```

### 场景 C：接收方已安装 App 但未登录

```
1. 接收方点击分享链接
2. 落地页尝试唤起 App（无 JWT）
3. App 启动到登录页
4. 用户登录后，App 解析缓存的深度链接参数
5. 调用 GET /api/v1/share/share_abc123def456/resolve（普通解析）
6. 解析成功，打开房间页面
```

### 场景 D：接收方未安装 App

```
1. 接收方在微信中点击分享链接
2. 落地页尝试唤起 App，检测到未安装
3. 跳转应用商店下载页
4. 用户下载安装 App
5. 首次打开 App，登录后跳转至分享的房间
```

## 9. 与现有功能的关系

| 功能 | 关系 |
|------|------|
| 房间邀请功能 | **不同场景**：邀请是点对点推送给指定用户，分享是生成公开链接可发给任何人 |
| 房间生命周期管理 | 分享链接加入房间走的是现有 `/api/v1/room/{id}/join` 逻辑，受房间状态约束（closed 的房间不可加入） |
| 敲门功能 | **不同概念**：敲门需房主审批，分享链接加入可直达房间 |
| JWT 鉴权 | 分享链接本身公开可访问，普通解析需要 JWT；落地页通过 `token` 参数传递 JWT 给 App |
