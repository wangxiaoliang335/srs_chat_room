# 房间生命周期管理 — 客户端对接文档

> 基于 `房间生命周期管理_服务端需求.md`，本文档说明服务端实现细节及与原文档的差异，供客户端对接参考。

## 1. 接口变更总览

| 接口 | 方法 | 路径 | 状态 | 说明 |
|------|------|------|------|------|
| 检测房间存活 | GET | `/api/v1/rooms/{room_id}/health` | ✅ 新增 | 检测房间是否可用 |
| 获取用户房间 | GET | `/api/v1/users/{user_id}/room` | ✅ 新增 | 查找好友所在的房间 |
| 关闭房间 | DELETE | `/api/v1/rooms/{room_id}` | ✅ 已实现 | 广播 `room_closed` |
| 关闭房间（别名） | DELETE | `/api/v1/room/{room_id}` | ✅ 已实现 | 单数路径也支持 |
| 离开房间 | POST | `/api/v1/rooms/{room_id}/leave` | ✅ 已实现 | 房主离开广播 `owner_offline` |
| 加入房间 | POST | `/api/v1/rooms/{room_id}/join` | ✅ 已实现 | 房主重新加入广播 `owner_online` |

> 文档路径 `/api/v1/rooms/*` 和现有路径 `/api/v1/room/*` 均支持。

## 2. 新增接口详情

### 2.1 检测房间是否存活

```
GET /api/v1/rooms/{room_id}/health
```

**请求：** 无需请求体，通过 JWT Bearer Token 认证。

**成功响应（200）：**
```json
{
  "code": 0,
  "message": "success",
  "data": {
    "room_id": "room_xxx",
    "status": "active",
    "owner_id": "user_xxx",
    "owner_status": "online",
    "member_count": 3
  }
}
```

**不存活响应（404）：**
```json
{
  "code": 404,
  "message": "room not found or closed",
  "data": null
}
```

---

### 2.2 获取指定用户的房间（查找好友房间）

```
GET /api/v1/users/{user_id}/room
```

**请求：** 通过 JWT Bearer Token 认证。

**成功响应（200，有房间）：**
```json
{
  "code": 0,
  "message": "success",
  "data": {
    "room_id": "room_xxx",
    "room_name": "闲聊室",
    "owner_id": "user_xxx",
    "owner_status": "online",
    "your_role": "member",
    "member_count": 3,
    "online_count": 1
  }
}
```

**无房间（用户在系统中存在但不在任何房间）：**
```json
{
  "code": 0,
  "message": "success",
  "data": null
}
```

**用户不存在（404）：**
```json
{
  "code": 404,
  "message": "user not found",
  "data": null
}
```

## 3. WebSocket 事件（新增 & 变更）

连接方式：`ws://{host}:8085/ws`（同现有连接，认证方式不变）

### 3.1 `owner_offline` — 房主离线（新增）

**触发时机：** 房主调用离开房间接口。

**推送对象：** 房间内**非房主成员**（房主本人不收到这条消息）。

```json
{
  "type": "owner_offline",
  "room_id": "room_xxx",
  "data": {
    "owner_id": "user_xxx",
    "owner_name": "user_xxx",
    "timestamp": 1785306254
  },
  "timestamp": "2026-07-28T10:00:00Z"
}
```

**客户端处理建议：**
- 在房间成员列表中，将房主的状态标记为"离线"
- 禁止对房主操作（如禁言、踢人按钮置灰）
- 房主角色不可转让

---

### 3.2 `owner_online` — 房主重新上线（新增）

**触发时机：** 房主重新加入房间。

**推送对象：** 房间内**非房主成员**。

```json
{
  "type": "owner_online",
  "room_id": "room_xxx",
  "data": {
    "owner_id": "user_xxx",
    "owner_name": "user_xxx",
    "timestamp": 1785306254
  },
  "timestamp": "2026-07-28T10:00:00Z"
}
```

**客户端处理建议：**
- 在房间成员列表中，将房主的状态恢复为"在线"
- 恢复对房主的操作权限

---

### 3.3 `room_closed` — 房间已关闭（新增）

**触发时机：** 房主关闭房间（DELETE `/api/v1/rooms/{room_id}`）。

**推送对象：** 房间内**所有在线成员**（包括房主自己也会收到）。

```json
{
  "type": "room_closed",
  "room_id": "room_xxx",
  "data": {
    "closed_by": "user_xxx",
    "reason": "owner_entered_another_room",
    "timestamp": 1785306254
  },
  "timestamp": "2026-07-28T10:00:00Z"
}
```

**客户端处理建议：**
- 显示"房间已关闭"提示
- 断开 WebSocket 连接
- 清理房间状态，返回主界面

## 4. 房主离开逻辑（变更说明）

### 原文档 vs 实现差异

| 行为 | 原文档描述 | 实现 |
|------|-----------|------|
| 房主离开后谁是房主 | 不转让，保留房主占位 | ✅ 同 |
| 成员列表显示 | 房主标记为 `owner_offline` | ✅ 同 |
| 其他成员能否获得房主权限 | 不能 | ✅ 同 |
| 房主重新加入 | 恢复 `owner_online` | ✅ 同 |
| 广播 `owner_offline` | 推送给非房主成员 | ✅ 同（已修正） |
| 推送 `member_left` | 不推送（房主不触发 member_left） | ⚠️ 实现会推送 `member_left` 给全房间，但 `owner_offline` 单独推送给其他成员 |

> **注意：** 房主离开时，系统会推送 `owner_offline` 给其他成员，但同时也会推送 `member_left`（因为房主从在线成员列表移除）。客户端应以 `owner_offline` 为准处理房主状态。

---

## 5. 关闭房间逻辑（变更说明）

### 原文档 vs 实现差异

| 行为 | 原文档描述 | 实现 |
|------|-----------|------|
| 事件名 | `room_closed` | ✅ 同 |
| 触发者 | 仅房主 | ✅ 同 |
| 保留房主占位 | 保留 | ✅ 同（房主仍存在于成员列表） |
| 关闭后房间状态 | `closed` | ✅ 同 |
| 广播 `room_closed` | 推送给所有在线成员 | ✅ 同 |
| 已关闭的房间能否加入 | 不可 | ✅ 已实现（join 时拒绝） |

> **注意：** 关闭房间后，房主仍在成员列表中（`is_owner=true`），但 `owner_status` 为 `offline`，`room_status` 为 `closed`。房主可以重新加入房间（房主重新加入不受 `closed` 状态限制）。

## 6. 客户端流程参考

### 6.1 申请加入好友房间

```
1. GET /api/v1/users/{user_b_id}/room
   → data == null       → 提示"该好友暂未开启房间"
   → data.user not found → 提示"用户不存在"
   → data != null       → 得到 room_id

2. GET /api/v1/rooms/{room_id}/health
   → 404                → 提示"房间已关闭"
   → 200                → 继续

3. POST /api/v1/rooms/{room_id}/knock（敲门请求）
```

### 6.2 房主进入另一房间（需先关闭旧房间）

```
1. 如果当前是房主且有 active 房间：
   a. DELETE /api/v1/rooms/{current_room_id}（关闭旧房间）
      → 收到 room_closed 事件
   b. POST /api/v1/rooms/{target_room_id}/join（加入新房间）
```

### 6.3 房主离开房间

```
1. POST /api/v1/rooms/{room_id}/leave
2. 收到 owner_offline 事件（其他成员）
3. 房主本人收到 member_left 事件
```

### 6.4 房主重新进入房间

```
1. POST /api/v1/rooms/{room_id}/join
2. 其他成员收到 owner_online 事件
3. 所有成员收到 member_joined 事件
```

## 7. 数据模型

### 房间状态字段（GET /api/v1/rooms/{room_id}）

```json
{
  "room_id": "room_xxx",
  "name": "闲聊室",
  "owner_id": "user_xxx",
  "owner_status": "online",        // "online" | "offline"
  "status": "active",             // "active" | "closed"
  "closed_by": "",                // 关闭者 user_id（仅 closed 时有值）
  "closed_at": "",                // 关闭时间（仅 closed 时有值）
  "close_reason": "",             // 关闭原因（仅 closed 时有值）
  "created_at": "2026-07-28 10:00:00",
  "max_members": 100,
  "allow_speak": true,
  "member_count": 3
}
```

### 成员字段（GET /api/v1/rooms/{room_id}/members）

```json
{
  "user_id": "user_xxx",
  "room_id": "room_xxx",
  "role": "owner",                // "owner" | "admin" | "member" | "guest"
  "status": "normal",             // "normal" | "muted" | "mic_off"
  "publish_allowed": true,
  "joined_at": "2026-07-28 10:00:00",
  "last_active": "2026-07-28 10:05:00"
}
```

## 8. 错误码汇总

| HTTP 状态码 | code | message | 说明 |
|-------------|------|---------|------|
| 200 | 0 | success | 成功 |
| 400 | 400 | room is closed | 尝试加入已关闭的房间 |
| 401 | 401 | not authenticated | JWT 缺失或无效 |
| 403 | 403 | 只有群主可以关闭房间 | 非房主尝试关闭房间 |
| 404 | 404 | user not found | 用户不存在 |
| 404 | 404 | room not found or closed | 房间不存在或已关闭 |
| 409 | 409 | 房间内存在活跃资源，无法删除 | 有活跃流时不能关闭房间 |
