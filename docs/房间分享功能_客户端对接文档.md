# 房间分享功能 — 客户端对接文档

> 基于 `房间分享功能_服务端需求.md`，本文档说明服务端实现细节及与原文档的差异，供客户端对接参考。

## 1. 接口总览

| 接口 | 方法 | 路径 | JWT | 说明 |
|------|------|------|-----|------|
| 生成分享链接 | POST | `/api/v1/share` | ✅ 必填 | 房主分享房间 |
| 公共解析 | GET | `/api/v1/share/{share_id}` | ❌ | 外部应用打开（落地页） |
| 普通解析 | GET | `/api/v1/share/{share_id}/resolve` | ✅ 必填 | App 内打开 |
| 通过分享加入 | POST | `/api/v1/share/{share_id}/join` | ✅ 必填 | 接收方加入房间 |

---

## 2. 接口详情

### 2.1 生成分享链接

```
POST /api/v1/share
Authorization: Bearer <chat_token>
```

**请求体：**
```json
{
  "room_id": "room_xxx",
  "message": "快来一起聊天！"
}
```

> `message` 为分享附言，最长 200 字，可为空。

**成功响应（200）：**
```json
{
  "code": 0,
  "message": "success",
  "data": {
    "share_id": "share_abc123def456",
    "share_url": "https://alove.app/room/share_abc123def456",
    "room_id": "room_xxx",
    "room_name": "闲聊室",
    "expires_at": 1785911054
  }
}
```

**错误码：**

| HTTP | code | message | 说明 |
|------|------|---------|------|
| 403 | 403 | not room owner | 非房主不能分享房间 |
| 400 | 400 | sharer not in room | 分享者不在房间 |
| 404 | 404 | room not found | 房间不存在 |
| 400 | 400 | message too long | 附言超过 200 字 |

**客户端行为：** 拿到 `share_url` 后，调用系统分享面板（微信、QQ、复制链接等）。

---

### 2.2 公共解析（落地页 / 外部应用打开）

```
GET /api/v1/share/{share_id}
```

> 无需鉴权。在微信、QQ、短信等外部环境打开分享链接时调用。

**成功响应（200）：**
```json
{
  "code": 0,
  "message": "success",
  "data": {
    "share_id": "share_abc123def456",
    "room_id": "room_xxx",
    "room_name": "闲聊室",
    "sharer_name": "Alice",
    "message": "快来一起聊天！",
    "room_status": "active",
    "member_count": 5,
    "expires_at": 1785911054
  }
}
```

**错误码：**

| HTTP | code | message | 说明 |
|------|------|---------|------|
| 410 | 410 | share link expired | 分享链接已过期 |
| 404 | 404 | room not found or closed | 房间不存在或已关闭 |

---

### 2.3 普通解析（App 内打开）

```
GET /api/v1/share/{share_id}/resolve
Authorization: Bearer <chat_token>
```

> 在 App 内通过深度链接唤起时调用，返回完整房间信息供 App 直接展示。

**成功响应（200）：**
```json
{
  "code": 0,
  "message": "success",
  "data": {
    "share_id": "share_abc123def456",
    "room_id": "room_xxx",
    "room_name": "闲聊室",
    "sharer_id": "user_xxx",
    "sharer_name": "Alice",
    "message": "快来一起聊天！",
    "room_status": "active",
    "member_count": 5,
    "owner_id": "user_xxx",
    "your_role": "member",
    "expires_at": 1785911054
  }
}
```

**your_role 含义：**
- `owner`：当前用户是房间房主
- `admin` / `member` / `guest`：当前用户已在房间中
- `none`：当前用户不在房间中

**错误码：**

| HTTP | code | message | 说明 |
|------|------|---------|------|
| 401 | 401 | not authenticated | JWT 缺失或无效 |
| 410 | 410 | share link expired | 分享链接已过期 |
| 404 | 404 | room not found or closed | 房间不存在或已关闭 |

---

### 2.4 通过分享链接加入房间

```
POST /api/v1/share/{share_id}/join
Authorization: Bearer <chat_token>
```

> 接收方在 App 内直接加入房间。

**请求体：** `{}`（空对象）

**成功响应（200）：**
```json
{
  "code": 0,
  "message": "success",
  "data": {
    "room_id": "room_xxx",
    "room_name": "闲聊室",
    "share_id": "share_abc123def456"
  }
}
```

> 如果用户已在房间中，也返回 200（幂等），客户端直接进入房间页面即可。

**错误码：**

| HTTP | code | message | 说明 |
|------|------|---------|------|
| 401 | 401 | not authenticated | 未登录 |
| 410 | 410 | share link expired | 分享链接已过期 |
| 404 | 404 | room not found or closed | 房间不存在或已关闭 |

## 3. WebSocket 事件

### `room_shared` — 房间被分享

**触发时机：** 房主调用 `POST /api/v1/share` 成功。

**推送对象：** 房间内**其他成员**（房主本人不收到）。

```json
{
  "type": "room_shared",
  "room_id": "room_xxx",
  "data": {
    "share_id": "share_abc123def456",
    "sharer_id": "user_xxx",
    "sharer_name": "Alice",
    "share_url": "https://alove.app/room/share_abc123def456",
    "timestamp": 1785306254
  },
  "timestamp": "2026-07-28T10:00:00Z"
}
```

**客户端处理建议：** 显示 Toast 提示"Alice 分享了房间"，无需跳转。

## 4. URL 结构与深度链接

### 4.1 链接格式

| 类型 | URL |
|------|-----|
| HTTP 分享链接（对外分享） | `https://alove.app/room/{share_id}` |
| App 深度链接（App 间唤起） | `aloveapp://room/{share_id}` |

### 4.2 客户端生成 App 深度链接

服务端只返回 `share_url`（HTTP 链接）。客户端在调用系统分享前，自行拼接 App 深度链接：

```
// share_url = "https://alove.app/room/share_abc123def456"
// jwt = 当前用户的 chat_token

// 系统分享内容
title: "Alice 邀请你加入闲聊室"
text: "快来一起聊天！"
url: share_url   // HTTP 链接，供落地页使用

// App 内跳转用的 scheme（不上传到系统分享）
scheme: "aloveapp://room/share_abc123def456?token={jwt}"
```

> `token` 参数用于 App 间唤起后自动鉴权，避免用户再次登录。

### 4.3 落地页（服务端提供，客户端无需实现）

`https://alove.app/room/{share_id}` 由服务端或前端 H5 实现（需另行开发），落地页职责：
1. 调用公共解析 `GET /api/v1/share/{share_id}` 获取房间信息
2. 展示分享者昵称、附言、房间名称、人数
3. 尝试唤起 App（`aloveapp://`），超时则跳转应用商店

## 5. 客户端流程参考

### 场景 A：分享方分享房间

```
1. 用户在房间内点击"分享"
2. POST /api/v1/share
   body: { "room_id": "room_xxx", "message": "快来一起聊天！" }
   → 200 { "share_url": "https://alove.app/room/share_abc123def456" }
3. 拼接 App scheme: aloveapp://room/share_abc123def456?token={jwt}
4. 调用系统分享面板，分享 share_url
5. 其他成员收到 WS room_shared 事件（可选提示）
```

### 场景 B：接收方已安装 App 且已登录（App 内打开）

```
1. 接收方点击 https://alove.app/room/share_abc123def456
2. 落地页尝醒 App（aloveapp://room/share_abc123def456?token={jwt}）
3. App 收到 aloveapp://，解析 share_id 和 jwt
4. GET /api/v1/share/share_abc123def456/resolve
   header: Authorization: Bearer {jwt}
   → 200，返回房间信息
5. 展示房间预览，用户确认后：
   POST /api/v1/share/share_abc123def456/join
   header: Authorization: Bearer {jwt}
   → 200，进入房间页面
```

### 场景 C：接收方已安装 App 但未登录

```
1. 接收方点击 aloveapp://room/share_abc123def456（无 token）
2. App 启动，显示登录页
3. 用户登录后，从启动参数中获取 share_id
4. GET /api/v1/share/share_abc123def456/resolve
   → 解析成功，展示房间预览
5. 用户确认后 POST .../join，进入房间
```

### 场景 D：接收方未安装 App

```
1. 接收方在微信中点击 https://alove.app/room/share_abc123def456
2. 落地页加载，调用公共解析
3. 展示房间信息 + "打开 App" 按钮
4. 尝醒 App 失败（超时），跳转应用商店
5. 用户下载安装后，从缓存参数获取 share_id，走场景 C
```

## 6. 与原文档的差异

| 项目 | 原文档描述 | 实现 | 说明 |
|------|-----------|------|------|
| `share_url` 内置 JWT | `https://alove.app/room/{share_id}?token={jwt}` | 不内置 JWT；App scheme 中自行拼接 | JWT 放 URL 参数有安全风险 |
| 深度链接生成 | 服务端生成完整 `aloveapp://` | 客户端自行拼接 | 客户端更灵活控制分享内容 |
| `room_shared` 推送 | 推送给所有成员 | 推送给**非分享者**成员 | 房主不应收到自己分享的事件 |

| 200 | 0 | success | 全部 |

| 403 | 403 | not room owner | POST /api/v1/share |
| 404 | 404 | room not found | POST /api/v1/share |
| 404 | 404 | room not found or closed | GET /resolve, POST /join, GET /share |
| 410 | 410 | share link expired | GET /resolve, POST /join, GET /share |
